# 자동화 가이드

이 레포에서 실제로 동작 중인 자동화는 **디자인 토큰 파이프라인** 하나입니다(`.github/workflows/style-dictionary.yml`). 이 문서는 그 파이프라인이 어떤 단계로 동작하는지, 그리고 각 단계가 왜 필요한지를 정리합니다.

## 전체 흐름

```text
tokens/** 수정 → token-sync 브랜치에 push
    ↓
GitHub Actions (style-dictionary.yml) 트리거
    ├── 1. npm run build           → Style Dictionary가 JSON을 Swift로 변환
    ├── 2. 토큰 diff 생성           → 변경 전/후 값을 표로 정리
    ├── 3. xcodebuild               → iOS Simulator 빌드로 생성 코드 검증
    ├── 4. 생성된 Swift 파일 커밋   → token-sync 브랜치에 auto-commit
    └── 5. PR 생성 또는 갱신        → token-sync → default
    ↓
개발자 PR 리뷰 & 머지
    ↓
(수동) 태그 → SPM 배포
```

트리거 조건은 `token-sync` 브랜치로의 push 중 `tokens/**` 경로 변경, 또는 `workflow_dispatch` 수동 실행입니다.

## 1. Style Dictionary 빌드 (`build.js`)

```bash
npm run build   # = node build.js
```

`tokens/base/*.json`, `tokens/semantic/*.json`을 소스로 읽어, 플랫폼별로 여러 Swift 파일을 생성합니다. 모두 **자동 생성 파일**이며 파일 상단에 `Auto-generated by Style Dictionary. Do not edit manually.` 주석이 붙습니다 — 직접 수정하지 말고 항상 `tokens/**.json`을 고쳐서 재생성하세요.

| 대상 | 생성 파일 | 내용 |
|---|---|---|
| `swift` | `MDS/Sources/Foundation/Base/BaseColor.swift` `BaseTypography.swift` `BaseSpacing.swift` `BaseRadius.swift` | Base 레이어 원시값 |
| `swiftSemantic` | `MDS/Sources/Tokens/Typography.swift` `SemanticColor.swift` | Semantic 레이어 (public API) |
| `swiftCatalog` | `MDS/Sources/Catalog/BaseColorCatalogData.swift` `BaseTypographyCatalogData.swift` | 카탈로그 앱 전용 `@_spi(MDSCatalog)` 데이터 |
| `swiftStoryBook` / `swiftStoryBookTypography` | `MDSStoryBook/MDSStoryBook/Token/Color/ColorTokenDataSource.swift` `Token/Typography/TypographyTokenDataSource.swift` | MDSStoryBook 카탈로그 앱의 토큰 목록 데이터 |

새 토큰 카테고리(예: 이번에 추가된 `radius`)를 추가하려면 `tokens/base/`에 JSON을 추가하고, `build.js`의 `StyleDictionary.registerFormat(...)`으로 포맷터를, `platforms.swift.files`에 출력 대상을 등록해야 합니다.

## 2. 토큰 diff 생성

워크플로우 내 인라인 Node 스크립트가 `git diff`로 변경된 `tokens/**.json` 파일을 찾아, 토큰 경로별 이전 값/변경 값을 비교해 마크다운 표(`/tmp/token_diff.md`)로 만듭니다. 이 표는 5단계에서 자동 생성 PR 본문에 그대로 삽입되어, 리뷰어가 Swift 코드 diff 대신 **토큰 의미 단위**로 변경을 확인할 수 있게 합니다.

## 3. xcodebuild 검증

```bash
xcodebuild build -scheme MDS -destination 'generic/platform=iOS Simulator' -skipPackagePluginValidation
```

Style Dictionary가 생성한 Swift 코드가 실제로 컴파일되는지 macOS 러너에서 검증합니다. 여기서 실패하면 이후 커밋/PR 단계로 진행하지 않습니다.

## 4. 생성 파일 자동 커밋

`stefanzweifel/git-auto-commit-action`으로 위 표에 나열된 생성 파일만 골라 `token-sync` 브랜치에 `[Style Dictionary] Update generated Swift token files` 커밋을 남깁니다.

## 5. PR 자동 생성

`gh pr create`로 `token-sync` → `default` PR을 엽니다. 이미 열려 있는 PR이 있으면 새로 만들지 않고 건너뜁니다(동일 브랜치에 여러 번 push해도 PR이 누적되지 않도록). PR 본문에는 2단계에서 만든 토큰 diff 표가 포함됩니다.

## 자동화되지 않은 부분

- **태그 생성 및 SPM 배포**: PR이 머지된 뒤 태그를 찍고 배포하는 과정은 아직 수동입니다.
- **아이콘 추가**: 아이콘은 Style Dictionary 파이프라인을 타지 않습니다. `Icon.xcassets`에 asset을 추가하고 `MDSIcon` enum을 직접 수정해야 합니다 — 자세한 절차는 [아이콘 가이드](icons.md#새-아이콘-추가하기) 참고.
- **컴포넌트 코드**: 컴포넌트는 항상 수동으로 작성합니다. 자동화 대상은 토큰(색상/타이포그래피/spacing/radius)뿐입니다.

## 향후 계획

README의 [워크플로우](../README.md#워크플로우) 섹션에 있는 대로, Figma 플러그인 → 서버 → GitHub API 연동이 붙으면 `token-sync` push 트리거가 `repository_dispatch` 이벤트로 바뀌고, 토큰 변경이 감지될 때만 `token-sync/{날짜}` 형태의 에페머럴 브랜치를 만드는 방식으로 전환될 예정입니다. 이 문서는 **현재 동작 중인 파이프라인** 기준으로 작성되었으므로, 해당 전환이 이뤄지면 함께 갱신해야 합니다.
